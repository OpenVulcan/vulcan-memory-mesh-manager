# Vulcan Memory Mesh Manager

`vmmm` 是 VulcanMemoryMesh OSS 本地版的独立安装器与管理器。它是单文件 Go 程序，与 VMM 分开构建、签名和发布。首次打开 TUI 时，管理器先下载并验证 VMM 完整包，再收集配置，使用包内 `vmm-local config validate` 检查候选配置并提交安装。

**发行方式：**独立管理器修复发行版本为 `v0.1.1`，修复 Windows 引导 URL 缺少 GitHub 域名的问题；旧 `v0.1.0` 标签与资产保持不变，请使用新版本脚本。管理器使用 Certum Windows 云签名与 Linux GPG 签名。仓库中的 `scripts/install.sh`、`scripts/install.ps1` 是含版本和 SHA-256 占位符的模板，直接运行会拒绝；请使用 [正式 Release](https://github.com/OpenVulcan/vulcan-memory-mesh-manager/releases) 中根据最终签名产物生成的实际引导脚本。工作流先创建并回验 Draft Release，再公开版本；验证模式仅保存 Actions 产物，详见[正式发行签名](docs/release-signing_CN.md)。VMM 运行时请选择 `v0.1.1` 或后续完整包；旧 VMM `v0.1.0` 不具备完整安装契约。

引导脚本仅下载固定版本的管理器程序，下载流设有 512 MiB 上限和十分钟总时限，超过上限、超时或 SHA-256 不匹配都会终止，不会执行文件。POSIX 脚本另外限制下载子进程可写文件大小；旧版 curl 对未声明长度的响应可能不会严格执行 `--max-filesize`，因此仍有子进程文件上限和下载后字节数复核。`install.ps1` 模板与正式生成物均使用带 BOM 的 UTF-8，以兼容 Windows PowerShell 5.1。此限制只约束首次引导下载，不改变管理器对 VMM 完整安装包的独立签名和长度校验。

## 首次安装

Windows PowerShell 推荐先下载再执行，兼容 5.1 和 7：

```powershell
irm https://github.com/OpenVulcan/vulcan-memory-mesh-manager/releases/download/v0.1.1/install.ps1 -OutFile .\install-vmmm.ps1
.\install-vmmm.ps1
```

PowerShell 7 也可以使用 `(irm <上述脚本地址>).TrimStart([char]0xFEFF) | iex`。不能直接使用 `irm | iex`：PowerShell 7 会保留响应的 UTF-8 BOM，而 Windows PowerShell 5.1 会按不同编码解析无字符集声明的响应；5.1 请使用下载后执行方式。Linux/macOS 使用 `curl -fsSL https://github.com/OpenVulcan/vulcan-memory-mesh-manager/releases/download/v0.1.1/install.sh | sh`。

1. 选择简体中文或英文，选择 GitHub 官方源、预置的 GitHub HTTPS 代理，或填写自定义 HTTPS 代理前缀。TUI 实时检测可达性；所有下载都要验证固定公钥签发的 Ed25519 清单、文件长度及 SHA-256。
2. 选择 VMM 版本和目录。管理器先下载完整包并验证归档、收据与包内文件，之后才进入配置页。
3. 选择五种存储方式之一，填写相应数据库路径或连接参数；通过快捷向导配置 LLM、Embedding、Rerank 供应商。API Key 与 PostgreSQL/ParadeDB DSN 存入受保护的 `.env`，YAML 只保存环境变量引用。
4. 选择命令行或服务运行方式、服务自启动策略，以及是否将永久安装的 `vmmm` 加入 PATH。高级配置编辑器按当前 VMM 的 `config schema --json` 展示字段，展开已有数组元素的具体路径，支持标量、对象和数组编辑，并保留 YAML 的注释与顺序。长字段列表随选中项滚动；编辑结构化 YAML 时按 `Ctrl+O` 换行，按 `Enter` 暂存字段。敏感字段在列表中脱敏，只接受 `${环境变量名}` 引用；包含敏感子字段的父级集合保持脱敏，支持用环境变量引用整体编辑，也可通过具体子字段修改。快捷向导保存 LLM 时以单条路由替换路由列表；保存 Embedding 时更新供应商、端点、模型、维度与密钥，清空会覆盖新密钥的旧节点，保留吞吐和批大小设置；保存重排时更新开关，选择新路由时替换路由列表，并保留 `top_n`。复杂路由仍可在高级编辑器中维护。
5. 每次修改配置都会使上次校验及写入预览失效。VMM 的真实配置与规则资产校验通过后，确认页提供配置写入差异预览：逐字段展示已保存用户覆盖与候选覆盖的新增、修改和删除，支持滚动查看长值；秘密值始终隐藏，规则文件以内容摘要展示变化，凭据写入仅列变量名。此预览描述用户覆盖文件的写入，不代表系统底座与环境变量的最终合并来源。确认后才提交安装。首次安装会立即按所选方式启动并等待本地健康检查通过；失败时不报告安装成功。服务“开机自启”只决定之后开机时是否自动启动。

安装确认页还可查看“候选生效配置及来源”，已安装首页可查看已保存配置的生效结果。两者调用真实 VMM 配置加载器，展示每个非敏感叶子的最终值、文件或环境来源及归一化标记，支持滚动和中英文切换。候选查看重新校验隔离目录，不保存配置、不安装程序；文件来源显示实际参与解析的文件（候选路径属于临时目录）。结果使用当前管理器进程的环境，服务账户环境不同可能得到不同结果。旧版运行时若仅返回第一版配置结果，明确显示“运行时未提供来源”，不在管理器内猜测来源。

| 界面选项 | VMM 存储配置 | 数据地址 | 检索方式 |
| --- | --- | --- | --- |
| 原生 | `storage.mode=native` | `sqlite.native.path`、`lancedb.native.path` | SQLite 原生 FTS 与 LanceDB 向量，经混合检索管线融合 |
| VLDB 分离式 | `storage.mode=split` | `storage.local_data_root` | VLDB 关系检索与 LanceDB 向量，经混合检索管线融合 |
| VLDB 控制器 | `storage.mode=controller` | `storage.local_data_root`、控制器参数 | 控制器关系及向量检索，经混合检索管线融合 |
| PostgreSQL | `storage.mode=combined`、`postgres.flavor=standard` | `.env` 中的 PostgreSQL DSN | PostgreSQL 关系及向量索引，按记忆管线融合 |
| ParadeDB | `storage.mode=combined`、`postgres.flavor=paradedb` | `.env` 中的 ParadeDB DSN | `pg_search` BM25 与向量检索融合 |

top-k、RRF、MMR、时间衰减、去重和阈值等由 VMM 配置字段控制，可在高级配置中调整。切换数据库模式或已有数据根不会自动迁移数据，需先停止、备份并按 VMM 文档显式迁移。

## 安装未完成与重新安装

管理器不使用事务恢复日志，也不在重启后自动恢复安装步骤。已有安装登记只保存一个完成标记，全部步骤成功后才标记完成；打开管理器会核对受管程序文件的摘要及必要配置是否存在。标记未完成、文件缺失或损坏时显示“安装未完成 / 需要修复”，可选择“重新安装 / 修复”重新下载签名包。正常安装但未启动的实例显示已安装、已停止。卸载开始删除受管程序文件前也会清除完成标记；程序只删除一部分或可选目录清理失败时，保留登记供明确重试，不报告卸载成功。

管理器自身的永久 `vmmm` 安装也只在所有权记录中保存一个完成标记。首次复制中断，或卸载已删除部分文件后中断时，状态检查只报告未完成，不会自动回放操作；再次执行安装会验证已登记的剩余文件和新下载包，再重新安装管理器程序。重新安装成功前会重新读取记录与程序摘要。卸载失败可明确重试；未经登记的文件和摘要不符的受管文件都不会被覆盖或删除。若发现预发行版本留下的旧卸载日志或暂存目录，会停止并要求人工检查，不自动处理其中的文件。

重新安装可替换已登记的损坏程序文件，保留配置和数据库；非受管文件冲突仍会阻止覆盖。如果配置丢失，须先恢复原配置，管理器不会猜测原数据库位置。服务或受管进程无法核实时显示“无法确认安装完整”，不会把查询失败当成正常停止。`vmmm status` 与 `vmmm doctor` 对未完成安装返回非零退出码并输出原因。

服务程序已经损坏时，管理器不会执行损坏的程序。若系统服务确实不存在，可用重新验证的暂存程序只读确认后直接重装；若系统服务仍存在，当前需要先通过操作系统停止服务，将经过验证的安装包恢复到原程序目录，再重新安装。VMM 服务控制会核对程序路径，不能用临时目录中的程序冒充原服务。此情况会明确提示，不会报安装成功。

若程序完整，但安装在服务注册之前中断，或原服务已被移除，VMM 会明确报告服务不存在。此时可直接选择重新安装为服务或命令行模式；查询权限不足或存在同名外部服务时不会当成不存在。

## 已安装后的命令

已安装页面的“配置”及 `vmmm config edit` 会先按保存的下载源重新验证并下载当前版本，再编辑候选配置；因此该编辑流程需要联网。候选校验同时包含暂存密钥及已有规则覆盖，正式配置在确认提交前保持不变。既有数据库和日志路径会保留，数据库身份变更仍要求显式迁移。回滚必须选择首页的回滚入口或 `vmmm rollback`，只回滚程序版本，不还原数据库。

已安装首页还提供直接“检查已保存配置”“设置 PATH 命令入口”和“升级到新版本”。配置检查调用已登记 VMM 的权威校验器，不下载安装包，也不进行供应商在线调用；通过后记录最近一次通过时间，未通过时保留旧时间并展示本次错误。这个时间只代表历史静态检查成功，不代表当前服务或数据库可用。`vmmm config validate` 和 `vmmm doctor` 也会执行该检查并更新成功时间；安装未完成时拒绝记录通过。PATH 设置只撤销管理器拥有的登记，升级仍须选择来源和版本并通过签名包验证。

首页的“诊断配置与运行状态”在同一次操作中分别展示权威配置检查结果和 VMM 本地 gRPC 健康类别、固定诊断码及耗时。配置通过但服务不可达会明确显示为两种不同结果；诊断不调用供应商，也不把健康失败当作 YAML 解析失败。

配置检查页可编辑 `prompts/`、`pii_rules/`、`noise_rules/` 中的完整文本文件。列表按用户覆盖优先显示，修改系统模板会生成用户覆盖文件；`Ctrl+O` 换行，`Ctrl+U` 清空当前文本，`Enter` 暂存。规则与 YAML、凭据一起交给 VMM 校验，校验失败时不提交。

高级配置中标记“可为空”的标量可按 `Ctrl+N` 暂存为显式 YAML `null`，适用于可选路由权重和相似度阈值等字段。它与数值 `0`、空字符串及字符串 `"null"` 分别处理；重新输入数值即可取消置空。最终是否允许空值以所选 VMM 的 schema 和配置校验结果为准，普通必填字段不能通过此快捷键清空。

`vmmm config show-effective` 直接调用已安装 VMM 的同名命令，显示按运行时规则合并、展开变量和归一化后的配置，输出带版本的 JSON；`--json` 输出紧凑格式。API 密钥、管理令牌、载荷加密密钥和数据库 DSN 等 schema 标注的敏感字段会被省略，其他字段显示原值。结果使用本次命令的环境，服务若使用不同环境需在相同环境中核对。旧运行时没有此命令时会明确失败，需要升级，不会改用用户覆盖文件冒充有效配置。

配置检查页提供可选的供应商在线测试。打开确认页不会发送请求，默认选项为返回；明确选择 LLM、embedding 或重排后才使用候选配置和暂存凭据发送固定测试内容。测试可能收费，密钥故障转移可能产生多次请求，总时限二十秒；只测试所选用途的首条路由，结果与静态配置校验分开显示。测试不会提交凭据、改写安装配置或写入数据库，失败后重试须回到确认页重新选择。

```text
vmmm                         打开 TUI
vmmm status                  查看安装与运行状态
vmmm start|stop|restart      控制当前运行模式
vmmm enable|disable          切换服务自启动
vmmm service <action>        安装、卸载、控制服务
vmmm service install --user <账户>  Linux/macOS 明确指定服务账户
vmmm config <action>         schema、validate、show-effective、edit
vmmm path enable|disable    管理 vmmm 命令入口
vmmm doctor                 检查状态与配置
vmmm upgrade|rollback       打开 TUI 选择发行包
vmmm uninstall              默认保留配置和数据
```

完整参数见 `vmmm --help`。Linux/macOS 的管理器程序、安装登记与锁由 root 持有；服务使用安装时明确选定的任意本机账户，配置与数据根由该账户持有。两种运行方式均将 `logging.directory` 设为数据根下的 `logs`，使后续转为服务时无需写入管理员持有的程序包；旧安装若缺少此字段，须先在高级配置中设置可写的绝对日志路径。TUI 会要求确认账户，命令行注册服务可用 `--user` 指定。普通用户运行永久安装的 `vmmm` 时，管理器先核验该程序及其父目录，再通过 `/usr/bin/sudo` 打开 TUI 或执行管理命令；首次引导脚本在提权后重新复制并核对固定 SHA-256。选择加入 PATH 后，Linux 在 `/usr/local/bin/vmmm` 建立管理员控制的命令入口；macOS 在 `/private/etc/paths.d/vmmm` 登记管理器目录，由系统登录 shell 加入 PATH，新终端生效。切换命令行/服务方式前会检查配置、程序和数据路径的归属及访问权限。默认卸载保留配置和数据库；删除它们需显式选项。

Windows 如需注册、卸载或控制系统服务，请从“以管理员身份运行”的终端启动 `vmmm`；TUI 会在停止旧实例或提交新文件前检查 UAC 提权状态。仅使用命令行进程模式时可从普通终端运行。默认控制登记和安装锁位于用户配置根的 `state/`，与 `data/` 分离；明确选择删除 VMM 配置或数据时，清理在安装锁内完成，失败可再次执行卸载。

若服务被 Windows 服务管理器另外设为“禁用”，请先在 Windows 服务中改为“手动”，再通过管理器修改自启动或注销服务。管理器的关闭自启动操作保留手动启动能力，无法精确恢复 Windows 的原生“禁用”设置，因此会在修改登记前拒绝这种状态。

Linux/macOS 选择服务账户后，管理器会在进程停止时调整所登记配置根、数据根及其普通文件的归属，失败时恢复原归属。直接使用“安装服务”前需先停止命令行进程。目录内的链接和特殊文件会阻止自动转换；配置根、数据根以外的自定义数据库或日志路径须事先授予所选账户访问权限。

PATH 登记写入失败且原生命令入口未能撤销时，管理器会保留所有权收据并明确报告撤销失败。修复登记路径后，可再次执行 `vmmm path disable`；管理器会按收据核对并撤销原入口。

## 开发与发行

开发需要 Go 1.25：`go build -o vmmm.exe ./cmd/vmmm`、`go test ./...`。开发程序的 TUI 首装仍需要可用的正式签名 Release。正式流程从精确标签提交构建五平台单文件资产，为管理器和 VMM 分别使用独立 Ed25519 发布密钥。当前私钥只保存在各仓库 GitHub Actions Secrets；固定公钥与用途见 [发行公钥说明](docs/release-public-keys.md)。

五平台 CI 另有显式启用的真实 PATH 验收：Windows 使用执行器当前用户注册表及环境广播，Linux 使用管理员拥有的 `/usr/local/bin/vmmm` 链接，macOS 使用 `/private/etc/paths.d/vmmm` 并通过真实登录 shell 检查；均核对命令解析到刚构建的文件、执行版本命令并移除入口。Linux 执行器若将共享命令目录设为可写，先验证拒绝，再临时设定受控权限并恢复。测试完成后恢复原注册表或清理所拥有的入口。此验收只在明确启用的临时 GitHub 执行器运行，普通本地测试会跳过，不修改本机 PATH。

下载源预置 GitHub 官方、`ghproxy.net`、`gh-proxy.org`、`ghfast.top`。代理只传输 GitHub Release URL，不成为发行身份；其可用性随地区和时间变化，TUI 会实时检测。样本与限制见 [下载源调研](docs/DOWNLOAD_SOURCES_CN.md)。完整设计和执行记录见 [安装器实施计划](docs/plan/20260923-01-VMMM_INSTALLER_IMPLEMENTATION.md)。
